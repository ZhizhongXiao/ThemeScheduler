## 架构职责边界

不得混淆以下职责：

- Windows 任务计划程序：只负责何时启动程序。
- `core.py`：负责时段判断、完整外观执行计划、结果和退出码契约。
- `execution_lock.py`：负责当前会话 Windows 命名互斥体。
- `auto_transaction.py`：负责自动事务结构、状态哈希和转换。
- `automation/`：按 Windows 后端、运行结果、恢复、失败处理和主编排拆分自动切换职责。
- `automation/contracts.py`：显式声明自动运行 Mixin 所需依赖，不以隐式属性代替类型契约。
- `cli/auto.py`：负责只读计划和受确认保护的阶段 4 单次运行。
- `persistence.py`：负责通用 JSON 对象读取、时间戳和原子替换；正式业务不得通过诊断模块持久化。
- `config.py`：负责配置校验、迁移、默认值和原子保存。
- `state.py`：负责暂停、活动时段、执行结果和运行状态。
- `backup.py`：负责不可覆盖的首次安装恢复点清单契约。
- `log_policy.py`：负责 v2 日志字段、v1 兼容读取、验证/回滚状态、隐私、轮换和运行事务保留参数。
- `runtime_retention.py`：负责可审计的事务清理计划和受控执行；调用方必须保护当前事务。
- `appearance.py`：读取权威当前外观，并为四项已冻结外观注册表值提供快照、受控写入、验证和精确恢复。
- `accent_profile.py`：负责最小语义强调色的版本化结构和严格校验。
- `accent_service.py`：负责完整外观动态主题事务、注册表快照、清单和结果汇总。
- `accent_theme.py`：负责动态主题副本、完整事务备份、隔离 `IThemeManager2` 应用与索引回退。
- `manual_appearance_service.py`：负责设置页显式应用当前时段；不得解除暂停。
- `storage.py`：负责用途目录与路径约束。
- `explorer_recovery.py`：只负责用户显式触发的当前会话 Explorer 故障恢复。
- `scheduler/`：按常量校验、触发器、任务模型、规范生成、差异检查和事务式变更拆分单任务 v2 职责。
- `scheduler_windows.py`：负责隔离 Task Scheduler 2.0 COM 访问、规范化读取和完整 XML 备份恢复。
- `cli/scheduler.py`：负责离线计划、只读检查和受显式确认保护的真实任务管理。
- `configuration_service.py`：负责配置与任务的共享互斥、组合提交、读回和失败回滚。
- `lifecycle/`：按 `layout`、`payload`、`installation`、`transaction` 拆分布局、
  载荷/安装清单、安装登记和生命周期状态；旧 `install_contracts.py` 已退役，
  源码、测试和工具统一直接依赖该子包。
- `lifecycle/deployment/`：按日志、文件系统和部署服务拆分载荷暂存、目录交换、完成与回滚。
- `setup_contracts.py`、`setup_data.py`、`setup_service.py`：分别负责 Setup 输入/计划、用户数据边界和安装事务编排。
- `setup_windows.py`、`setup_gui_api.py`、`setup_gui.py`：负责当前用户 Windows 适配组合、Setup 白名单 API和 WebView2/pywebview 启动。
- `setup_preview.py`：只负责源码安全预览的内存安装演示，不得导入或调用真实 Windows 安装适配器。
- `uninstall_contracts.py`、`uninstall_service.py`、`uninstall_windows.py`：负责不依赖主程序的任务移除、可选外观恢复、程序/数据清理和自删除。
- `workbench/`：负责 pywebview 白名单 API 的解析、概览、配置、维护、Shell 和 Windows 装配。
- `workbench/contracts.py`：统一维护 GUI 注入 Protocol 和发往 JavaScript 的 TypedDict 线协议。
- `errors.py`：所有产品自定义异常的共同根；新增 `*Error` 不得直接继承裸
  `Exception`、`ValueError` 或 `RuntimeError`。
- `gui.py`：负责按需启动 Edge Chromium、本地前端和结果展示，不复制核心逻辑；`auto` 路径不得导入 GUI。
- `ui/html/`：负责工作 GUI、Setup 和 Uninstall 的本地语义结构，不加载远程页面。
- `ui/css/`：负责工作 GUI 样式及 Setup/Uninstall 共用向导令牌，不执行安装或卸载。
- `ui/js/`：负责本地交互和 pywebview 白名单调用，不承载主题、任务或生命周期业务逻辑。
- `ui/fonts/`：负责共享中文界面字体子集、许可和来源说明。
- `entrypoints/`：只解析命令和启动用例，不承载业务实现。

Windows 设置仍是用户手动选择主题和强调色的正式入口。程序只保存和恢复 Windows 已生成的结果。

## 禁止事项

未经明确设计变更，不得：

- 随意改变已冻结的架构、模块职责、安装范围或数据目录。
- 引入常驻托盘、后台轮询、注册表实时监听或第三方调度器。
- 增加三个以上时段、日出日落、云同步或多用户管理等首版非目标。
- 让不同计划任务分别硬编码昼间或夜间配置；所有触发器必须调用同一 `auto` 核心入口。
- 根据单一 RGB 值自行推导 Windows 完整强调色调色板；正式配置只保存 Windows 已生成的原始 `ColorizationColor`。
- 在自动入口捕获或覆盖已有昼夜外观配置。
- 用 GUI、安装器或命令入口复制时段判断、注册表读写或快照逻辑。
- 引入 Electron、PyQt/Qt、Tauri 等第二套 GUI 技术栈；阶段 7 已冻结使用 pywebview。
- 让 pywebview 降级到 MSHTML、加载远程页面、在正式构建开启调试，或让 `auto` 初始化 WebView。
- 在源码 GUI 中省略显式数据根，或在没有额外实机开关和明确可执行文件时允许任务/Windows 写入。
- 写入 Windows 系统目录，或无必要地要求管理员权限。
- 关闭或绕过 Defender、SmartScreen，或自动创建安全排除项。
- 使用 UPX、代码混淆、隐藏命令、动态下载并执行应用代码等发布手段；经用户确认和 Microsoft 签名验证的 WebView2 Evergreen 系统依赖安装是唯一冻结例外。
- 修改无关文件，或删除用户配置、备份、日志及构建资源而不确认范围。

## Windows 操作安全

涉及注册表、任务计划、安装目录或用户个性化设置时：

- 默认只操作当前用户范围。
- 任何首次修改必须先读取并保存真实原值，不能假定用户原本使用某种主题或颜色。
- 原型测试前应明确备份和人工恢复方法。
- 写入后必须读回验证，不能只以命令退出码判断成功。
- 多步操作应记录已完成阶段，避免留下可触发的残缺任务或半安装状态。
- 未经任务明确授权，不在开发机上创建、修改或删除真实计划任务，也不执行真实安装或卸载。
- 不以重启 Explorer 作为默认刷新方案；只能由用户在维护入口明确确认后作为故障兜底，计划任务不得静默执行。

## 修改原则

优先：

- 小步、可回滚、可验证的修改。
- 先完成最低成本原型，再冻结 Windows 集成细节。
- 复用业务组件，保持入口和 GUI 轻量。
- 保持自动执行按当前实际时间决策且可以重复运行。
- 同一可信目标时段必须 `no-change`，不得覆盖用户在固定边界之间的手动调整。
- 两种模式、强调色和两个显示位置必须通过同一个可回滚外观事务组合。
- Windows 已验证但状态尚未提交的窗口必须使用自动事务清单恢复，不得静默重跑。
- 对 JSON 使用结构版本、严格校验、迁移和原子写入。
- 正式数据拒绝未知字段和未知版本；config v1 与安装备份 v1 仅兼容读取，新增数据使用 v2，默认值不能掩盖已有文件损坏。
- 配置、状态和强调色配置只能显式初始化，或在现有文件已经通过严格校验后更新。
- 首次安装备份清单存在时任何普通路径都不得覆盖；主题哈希或视觉状态不匹配时必须失败。
- 状态不可信时采取保守策略，不写 Windows，也不污染已保存计划。
- 明确呈现部分成功和失败，避免模糊的成功提示。
- 保持 Windows 11 x64、当前用户安装和 PyInstaller `onedir` 的首版边界。
- 使用项目专用 `uv` 环境和 `uv.lock`；发布构建不得依赖全局 Python 包。
- 测试依赖 `uv sync` 的可编辑安装，不在测试模块中重新加入 `src` 路径注入。
- 递归清理发布工作目录前必须验证解析后的目标是项目根的严格后代。

避免：

- 在实机验证前硬编码未经确认的注册表值或 Shell 刷新方式。
- 为未来功能提前构建复杂抽象。
- 继续扩大过大的函数或让跨组件副作用难以回滚。
- 为了界面进度绕过核心层或持久化约束。
- 把路线图中的“当前倾向”误写成已冻结决策。

## 测试与验证

验证范围应与修改内容对应。

使用 `tools/test.py` 的分层入口：

- 小修改运行 `quick <group>`；
- 功能批次完成运行 `affected <group>`；
- 实机写入前、公共契约变更后或逻辑批次收口运行 `full`；
- 候选构建前运行 `release`，包含全套测试、`compileall`、锁文件检查、Pyright
  零诊断及 Ruff lint/format；
- 默认保持静默输出，失败后才以 `--verbose` 重跑；
- 不得以降低旧测试频率为由删除旧回归，或省略实机写入/发布候选前的全套检查。

非 release 的阶段 15 及公共 Python 契约修改还需运行
`uv run --group quality pyright`。该命令
检查完整源码并对选定核心边界启用 strict；扩大 strict 列表前先修复新增范围的全部
真实诊断，具体策略见 [CODE_QUALITY.md](CODE_QUALITY.md)。

### 时段与核心流程

至少覆盖：

- 昼间边界、夜间边界及各自前后一分钟。
- 跨午夜判断。
- 同一目标时段重复执行的幂等性。
- 跨一个或两个边界休眠、关机后的当前时间校准。
- 暂停状态、状态缺失、状态损坏和活动时段来源不可信。

### 主题与强调色

至少确认：

- 默认应用模式可读、可写、可读回，且 Windows 系统模式在切换和恢复前后不变。
- 昼夜同色、异色及用户在时段内手动改色。
- 语义强调色序列化不丢失原始 `ColorizationColor`，主题事务备份与清单哈希一致。
- 重复恢复不会交换或污染昼夜快照。
- Shell 刷新效果在目标 Windows 11 版本上经过实机观察。

实机验证必须记录 Windows 版本、测试前状态、写入内容、读回结果和人工观察结果。

### 持久化

至少覆盖：

- 文件不存在、非法 JSON、截断、未知结构版本和部分字段损坏。
- 原子写入中断后不会遗留半写文件。
- 升级迁移保留配置、颜色快照和首次安装备份。
- 日志轮换不会无限增长。

### 任务计划

至少确认：

- 只存在一个受管任务，且精确包含 `DayPrepare`、`DayBoundary`、`NightPrepare`、`NightBoundary` 四个每日触发器；存在延后状态时才额外包含成对的 `DeferredPrepare`、`DeferredBoundary` 一次性触发器；
- 所有触发器都调用同一 `auto` 入口，延后触发器不得脱离可信 `pending-switch` 状态单独存在。
- 不唤醒设备，且开启错过计划后尽快运行。
- 命令、参数、工作目录、用户上下文和绝对路径可读回验证。
- 更新时间后没有旧触发器残留。
- 创建、检查、修复和删除操作可重复执行。

### GUI 与安装生命周期

如果修改 GUI，至少确认输入校验、失败提示、键盘操作、常见 DPI、非管理员当前用户操作、关闭后不常驻，以及 `auto` 不初始化 WebView。前端 API 必须是最小白名单，不得暴露任意文件或命令执行。GUI 或自动入口调用 PowerShell 桥接时必须复用共享无窗口选项，回归确认不会闪出 CMD/PowerShell。

如果修改安装、升级、卸载或打包，至少确认：

- 首次修改前已备份真实个性化状态。
- 安装失败不会留下可触发的残缺任务。
- 升级保留用户数据并能处理正在运行的程序。
- 卸载的“恢复接管前应用模式和强调色”和“保持当前外观”两条路径都符合选择，且均保持 Windows 系统模式。
- 目标设备无需预装 Python。
- 正式主程序保持 PyInstaller `onedir`；单文件形态仅用于 Setup 和不依赖主 `_internal` 的独立卸载器。
- WebView2 Runtime 在 GUI 启动前被检测，缺失时通过 Evergreen 路径明确修复且不降级到 MSHTML。
- `pyproject.toml`、`uv.lock`、锁定工具版本和发布哈希能够复现候选版本。

## 文档一致性

决策变更后必须同步更新对应文档：

- 系统边界、组件职责、部署或质量属性变更：更新 `ARCHITECTURE.md`。
- 业务规则、算法、数据模型或界面行为变更：更新 `DESIGN.md`。
- 里程碑、退出条件、风险或待决策状态变更：更新 `BACKLOG.md`。
- 1.0 阶段顺序、门槛或完成定义变更：更新 `ROADMAP_1.0.md`。

待决策事项完成后，必须把结果写入架构或设计文档，不能只保留在代码、日志或讨论中。

- 是否修改了注册表、任务计划、安装目录或用户个性化设置。
