# ThemeScheduler 安装生命周期契约

## 1. 文档目的

本文定义当前用户安装、轻量维护、覆盖升级、损坏重装和独立卸载边界。主题、配置、任务和持久化契约继续分别由 [DESIGN.md](DESIGN.md)、[PERSISTENCE.md](PERSISTENCE.md) 与 [SCHEDULER.md](SCHEDULER.md) 定义。

产品不实现后台自更新服务，也不建立完整安装器缓存或重型自修复系统。用户通过新的单文件 Setup 完成安装、升级或重装；控制面板“更改”进入主程序维护页；控制面板“卸载”调用不依赖主程序目录内容的自包含卸载器。

## 2. 冻结产品决策

1. 默认按当前用户安装，不要求管理员权限。
2. 注册当前用户范围的 Windows“已安装的应用”条目。
3. 控制面板“更改”启动 `ThemeScheduler.exe maintenance`，提供恢复安装前外观、重置配置和修复任务，不承担程序文件修复。
4. 控制面板“卸载”启动独立、自包含的 `Uninstall.exe`；主程序或 `_internal` 损坏时仍可删除任务、程序、登记、快捷方式及用户选择的数据。
5. 不长期缓存完整 Setup；需要文件修复时，用户重新运行原安装器。
6. Setup 支持无需用户预清理的事务式重装。新文件先进入暂存目录并完整验证，不能直接覆盖损坏目录。
7. 首次安装备份由首次成功安装创建；升级、重装、修复和普通运行不得覆盖。
8. schema v2 恢复点恢复 ThemeScheduler 管理的两种模式、强调色及两个显示位置；旧 schema v1 维持原有恢复范围。壁纸等非本产品所有内容不变。
9. 恢复前先持久化暂停；恢复失败也保持暂停，防止下一边界继续修改外观。
10. 程序根目录由产品独占，可在卸载时整体删除；用户数据根按用户选择和固定清理矩阵处理。

## 3. 目录与所有权

正式安装布局：

```text
%LOCALAPPDATA%\Programs\ThemeScheduler\
├─ app\
│  ├─ ThemeScheduler.exe
│  └─ _internal\
│     ├─ Python 运行组件及依赖
│     ├─ ui\
│     └─ bridges\
├─ maintenance\
│  └─ Uninstall.exe
├─ metadata\
│  ├─ installation.json
│  └─ payload-manifest.json
├─ .staging-<transaction-id>\
└─ .rollback-<transaction-id>\
```

任务计划固定指向：

```text
%LOCALAPPDATA%\Programs\ThemeScheduler\app\ThemeScheduler.exe auto
```

用户数据继续位于：

```text
%LOCALAPPDATA%\ThemeScheduler\
├─ config.json
├─ state.json
├─ initial-setup.json       # 仅首次配置完成前存在
├─ profiles\
├─ backup\
├─ logs\
├─ runtime\
└─ WebView2\
```

程序根只保存可重新部署的程序和安装元数据，不保存用户配置。不得允许用户把任意已有非空目录声明为程序根并在卸载时递归删除；所有递归删除前必须规范化路径、验证根边界、拒绝重解析点逃逸并确认目标属于固定产品根。

## 4. 安装清单

安装生命周期使用两个严格、版本化清单：

- `payload-manifest.json`：发布版本、相对文件路径、字节数和 SHA-256。路径必须为规范相对路径，不允许绝对路径、`..`、空段或重解析点。
- `installation.json`：产品 ID、已安装版本、安装时间、程序根、数据根、主程序、卸载器、载荷清单哈希和当前安装事务结果。

发布清单用于暂存验证、安装自检和诊断；卸载器不因清单损坏而拒绝清理固定产品根，但必须报告清单不可信。未知文件在独占程序根内随根目录删除，不能被复制到新版本中。

`backup/install.json` 和 `backup/install.theme` 仍是不可覆盖的首次外观恢复点，不属于程序载荷清单。

## 5. Windows 安装登记

登记位置：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\ThemeScheduler
```

至少写入并读回：

```text
DisplayName
DisplayVersion
Publisher
DisplayIcon
InstallLocation
ModifyPath
UninstallString
EstimatedSize
NoModify = 0
NoRepair = 1
```

`ModifyPath` 指向主程序的 `maintenance` 用例；`UninstallString` 指向独立卸载器。第一版不登记静默卸载命令，因为外观恢复和用户数据保留需要用户选择。安装登记只在程序、卸载器、元数据和必要系统集成均可验证后提交；安装失败回滚时删除。升级复用同一产品键，不产生重复条目。

## 6. 生命周期流程

### 6.0 Setup 单窗口状态机

Setup 采用固定约 `720 × 540` 的单窗口五页向导：

```text
启动只读预检
→ 欢迎
→ 安装选项
→ 确认
→ 真实事务进度
→ 完成 / 警告 / 已回滚失败 / 部分失败
```

左侧固定显示品牌和纵向步骤，底部固定显示取消、上一步和下一步/安装/完成。Setup 只提供固定安装位置和桌面快捷方式选择，不再编辑时间、应用模式、强调色或立即同步。首次新建六项核心数据时使用安全默认配置，并写入首次设置暂停态及独立临时标记；完成页的主操作打开主 GUI，次操作仅结束安装。重装或升级保持桌面快捷方式的既有默认状态，并明确说明可信用户数据原样保留。

安装由后台会话执行既有原子事务，前端只轮询白名单状态并呈现核心报告的阶段，不以动画计时伪造百分比。确认前关闭不产生写入；安装或回滚期间不接受取消或关闭，原生窗口关闭事件也必须被否决。结果页必须区分成功、成功但有提醒、失败且回滚完成、回滚不完整，并提供固定、无任意路径参数的日志入口。本次 Setup 会话日志写入用户数据根的 `logs/setup-<会话>.json`；即使首次安装回滚，也只为诊断重建受既有卸载“保留日志”选项管理的日志目录，不在 `%TEMP%\ThemeScheduler` 另留普通安装日志。

### 6.1 首次安装

```text
验证系统、路径、载荷和 WebView2
→ 在程序根建立生命周期事务
→ 解包到 .staging 并逐文件验证
→ 初始化或严格验证用户数据
→ 在首次系统修改前创建不可覆盖的安装前外观备份
→ 激活 app、maintenance 和 metadata
→ 创建快捷方式与安装登记
→ 创建并读回任务
→ 运行安装自检
→ 提交事务并清理暂存/回滚目录
→ 完成页按用户选择打开主 GUI或仅结束
```

只有所有必需步骤完成并读回一致才能显示安装成功。由本次尝试创建的任务、登记、快捷方式、文件和数据在失败时按逆序回滚；既有可信用户数据不得作为失败清理的一部分删除。首次安装创建的任务不会立即改变外观：`state.json` 和 `initial-setup.json` 共同阻止自动入口，直到主 GUI 第一次成功保存。保留配置卸载会保留该标记，删除配置卸载会删除它；重装和升级保持原暂停状态。

### 6.2 控制面板“更改”

`ThemeScheduler.exe maintenance` 打开现有 pywebview 控制面板的维护区，不引入第二套 GUI。提供：

- 恢复安装前外观；
- 恢复默认时间和通知设置；
- 检查或修复任务；
- 打开数据和日志目录；
- 启动独立卸载器。

恢复安装前外观的事务：

```text
取得自动核心同一互斥
→ 拒绝未完成自动事务
→ 严格验证首次安装备份
→ 持久化 paused=true
→ 从当前活动主题创建管理副本
→ schema v2 应用备份中的 AppMode、SystemMode、语义强调色和两个显示位置
→ schema v1 保持当前 SystemMode；所有版本均保持壁纸等非所有字段
→ 读回验证并记录日志
```

如果首次安装备份缺失、损坏或哈希不符，维护页只能报告无法可信恢复，不能重建备份冒充原恢复点。

### 6.3 升级和损坏重装

用户可直接运行新的 Setup，无需预先卸载或手动清理损坏文件。流程为：

```text
检测现有安装和事务残留
→ 验证新载荷并解包到 .staging
→ 请求关闭 GUI并取得生命周期/自动互斥
→ 禁用任务并确认没有正在执行的实例
→ 将现有 app、maintenance 和 metadata 移到 .rollback
→ 将已验证的新组件切换到正式路径
→ 迁移并严格验证用户数据
→ 更新登记、快捷方式和任务
→ 运行自检
→ 成功后删除 .rollback；失败则恢复旧组件和系统集成
```

不得把新文件直接覆盖进旧 `app`。同版本重装和更高版本升级使用同一事务；降级默认拒绝，除非未来增加明确的兼容性和用户确认策略。升级、重装和修复不得覆盖首次安装备份。

旧组件本身已经损坏时，Setup 仍可用全新暂存载荷完成切换。若新安装失败且旧组件也不可信，任务保持禁用，保留双方证据并报告部分失败，不能重新启用可能损坏的自动入口。

### 6.4 独立卸载

`Uninstall.exe` 使用 Windows GUI 子系统、自包含运行依赖和最小卸载桥接，不从 `app\_internal` 导入任何代码、脚本或 DLL。入口先把自身复制到：

```text
%TEMP%\ThemeScheduler\uninstall-<transaction-id>\
```

再启动临时副本并退出安装目录中的进程。临时卸载器执行：

```text
取得生命周期/自动互斥
→ 禁用并删除任务
→ 按选择恢复或保持当前外观
→ 删除快捷方式和安装登记
→ 删除整个固定程序根
→ 按清理矩阵处理用户数据
→ 启动固定、可审计、无窗口的临时清理脚本
→ 临时卸载器退出后删除临时工作区
```

用户交互采用同一套经典向导视觉。安装目录中的第一进程显示欢迎、三个集中选项与
自然语言确认；确认后只暂存、验证并启动临时副本。第一窗口关闭后，临时副本继续
显示实际阶段进度、完成或部分失败结果。两个进程不会同时修改卸载状态；实际写入
只发生在临时副本验证一次性请求、源卸载器哈希、清理脚本哈希、15 分钟有效期和
固定安装/数据根之后。短暂窗口交接是释放安装目录文件锁所必需的实现细节，逻辑上
仍是一条单窗口向导流程。

正常确认、成功和可预期部分失败不使用连续消息框。后台卸载期间，前端导航、白名单
关闭 API和原生窗口关闭事件读取同一运行状态并拒绝退出；事务完成后，结果页保持
可见，用户点击“完成”退出才允许固定清理脚本删除临时工作区。

临时脚本不得使用 Base64、混淆、网络下载或任意拼接命令；脚本路径、目标根和等待进程 ID 均须严格验证。清理失败时记录确切残留，允许重启后或下次 Setup 再清理，不得虚假报告完整卸载。

## 7. 卸载选择与清理矩阵

外观选择：

```text
○ 恢复安装前的应用模式和强调色
○ 保持当前应用模式和强调色
```

数据选择：

```text
□ 保留配置和昼夜颜色记录，供以后重新安装
□ 保留日志
```

固定处理：

| 对象 | 始终删除 | 受选项控制 |
| --- | --- | --- |
| `\ThemeScheduler` 任务 | 是 | 否 |
| 程序根、损坏文件、安装元数据和桥接脚本 | 是 | 否 |
| 开始菜单/桌面快捷方式、安装登记 | 是 | 否 |
| `runtime/`、`WebView2/` | 是 | 否 |
| `config.json`、`state.json`、`profiles/`、临时 `initial-setup.json` | 否 | “保留配置和颜色” |
| `logs/` | 否 | “保留日志” |
| `backup/install.*` | 恢复成功后删除；未恢复时随保留配置策略处理 | 是 |

选择全部删除时，严格验证后删除整个 `%LOCALAPPDATA%\ThemeScheduler`。选择保留时，不得删除未知或损坏的保留数据，也不得把它们自动改写为有效文件。

## 8. 失败与恢复边界

- 文件被占用：请求关闭进程；仍被占用则中止切换或记录重启后清理，不做混合覆盖。
- 任务删除失败：卸载不得声称干净完成；程序根可暂缓删除以保留重试入口。
- 外观恢复失败：保持暂停，保留安装备份和错误证据；允许用户选择保持当前外观后继续卸载。
- 安装登记失败：首次安装回滚；升级恢复旧登记。
- 新版本自检失败：恢复旧组件、任务和登记；无法恢复时任务保持禁用。
- 首次安装备份损坏：禁止自动恢复，但不阻止用户选择保持当前外观并卸载。
- 卸载器自身损坏：重新运行 Setup 可重建独立卸载器和登记，不要求先清理旧程序。

## 9. 授权门槛

以下实机动作必须分别说明范围并取得用户明确授权：

1. 在 `%LOCALAPPDATA%\Programs\ThemeScheduler` 写入或递归替换程序文件；
2. 写入 HKCU “已安装的应用”登记和当前用户快捷方式；
3. 创建、修改、禁用或删除真实 `\ThemeScheduler` 任务；
4. 捕获或恢复安装前外观；
5. 递归删除正式程序根、用户数据根或临时卸载工作区；
6. WebView2 缺失时运行 Microsoft 安装程序。

离线模型、工作区暂存、假后端和只读检查不构成上述授权。
