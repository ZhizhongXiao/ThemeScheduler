# ThemeScheduler 维护清单

本文记录从正式 `0.1.3` 到 `1.0.0` 的当前执行状态。唯一阶段顺序和退出条件见
[ROADMAP_1.0.md](ROADMAP_1.0.md)；已完成版本结论见 [RELEASE.md](RELEASE.md)，
机器证据保存在正式发布与 `artifacts/acceptance/`。

## 当前基线

- `0.1.3` 已完成自动门禁、可复现构建、Defender 和变更驱动的 Windows 实机验收；
- 正式发布位于 `artifacts/releases/0.1.3`；
- `0.1.4` 的实时外观读取修复已完成定向实机验收；
- 当前源码为 `0.1.5` 功能候选：昼夜分别保存 Windows 模式、应用模式、强调色、
  开始菜单/任务栏显示开关和标题栏/窗口边框显示开关；
- 自动边界不再学习用户临时颜色，计划只由首次初始化或 GUI 显式导入/编辑更新；
- `0.1.5 RC2` 已通过 577 项 release 测试、Coverage 逐模块棘轮、连续双构建、
  PE/payload 校验和 Defender 扫描；
- 完整外观人工实机矩阵已通过并恢复原配置、任务和 Windows 外观；0.1.5 已冻结为
  1.0 功能基线，但不单独冻结为正式发布。

## 1.0 执行队列

严格按下列顺序推进；前一阶段未满足退出条件时不进入后一阶段：

1. **已完成**：0.1.5 昼夜完整外观实机矩阵通过，测试基线已恢复；
2. **待实施**：把平铺测试整理为 `unit/integration/release`，同步发现规则；
3. **待实施**：补 GUI 启动、Explorer 恢复和 Windows 组合适配器高风险分支；
4. **待实施**：借助新增安全网逐文件扩大 Pyright strict；
5. **待测量**：建立 Task Scheduler 桥只读性能基线，据阈值决定是否批量化；
6. **待实施**：统一升版为 1.0.0，重跑门禁、双构建、Defender 和最终生命周期。

## 路线边界

- 不单独对外发布 0.1.4；其读取修复作为 1.0 基线的一部分；
- 0.1.5 可以只作为功能资格里程碑，不要求创建 GitHub Release；
- 任务桥没有达到测量阈值时保持现状，不为完成清单强行重构；
- 进入最终构建后任何源码或发布文档变化都必须重新绑定门禁报告和双构建。

## 非目标

- 不增加三个或更多时段；
- 不增加日出/日落联网计算；
- 不接管 Windows 色温“夜间模式”；
- 不接管壁纸、声音、鼠标指针或桌面图标；
- 不增加后台自动更新服务；
- 不在 1.0 冻结期增加新功能；
- 不为降低统计数字删除关键测试、事务回滚或数据校验；
- 不在缺少机器可读计划和明确授权时清理发布产物或执行 Windows 实机写入。
