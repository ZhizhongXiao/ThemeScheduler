## 1.0 执行队列

严格按下列顺序推进；前一阶段未满足退出条件时不进入后一阶段：

1. **已完成**：0.1.5 昼夜完整外观实机矩阵通过，测试基线已恢复；
2. **已完成**：原 67 个测试文件已完成迁移；当前 70 个测试模块分布为
   unit 25、integration 34、release 11，发现等价性已证明；
3. **已完成**：GUI、Explorer、完整外观与任务桥的高风险失败分支已补齐；
4. **已完成**：五个高风险边界已逐文件达到 strict 零诊断，棘轮由 7 个扩大到 12 个；
5. **已完成**：20 样本复测显示任务桥仅占完整健康检查 p50 的约 23.0%，保留单操作桥；
6. **已完成（组合证据收口）**：build 26200 曾真实生成只有 `[Theme.A]`/`[Theme.W]`、
   不含 `[VisualStyles]` 的 `Custom.theme`；该结构已脱敏固化，并通过补全、应用验证和
   级联回滚自动测试。真实 `spotlight.theme`（有 `[VisualStyles]`、无 `ThemeId`）已由
   0.1.5 兼容候选成功应用；既有的“DWM 值可能滞后”结论也完成回归确认：公共颜色
   API 为 `#BFBFBF`、旧 DWM 值仍为 `#744DA9` 时，GUI 正确导入前者。Windows 未公开
   `.A/.W` 的稳定触发方式，因此不再通过反复切换或人为改写 `CurrentTheme` 追求
   第二次现场复现；
7. **已完成**：1.0.0 最终门禁、双构建、Defender、升级与零残留生命周期验收通过，
   正式发布目录、Git 标签和 GitHub Release 按同一源码身份冻结。

## 静态审计补充处理

- **已修复**：维护页“恢复默认时间与通知”仅重建时段/通知字段，其他完整昼夜外观字段和独立颜色 profile 均原样保留；
- **已修复**：错误通知的去重检查、发送、成功记账由专用限时等待命名 mutex 串行化；失败通知不记账，不同错误键的写入不会互相覆盖；锁异常不改变已完成的核心切换结果；
- **已修复**：事件日志的尺寸检查、备份轮转和追加写入由另一个独立命名 mutex 串行化；JSONL 格式、1 MiB 上限和五份正式备份策略未变；
- **已修复**：迁移目标替换失败后，重试会校验并复用与原文档相同的 `.bak`；已有备份内容不匹配或无法读取时拒绝覆盖，源文档保持不动；
- **DST 刻画（未改实现）**：CPython 3.12 的 `datetime.now().astimezone()` 在本机 Windows 运行时返回固定当前 offset（本机为 UTC+08:00）；未来边界计算会复用该 `tzinfo`，因此直接向 DST 切换后的日期投影会保留旧 offset。新增确定性测试展示了这个一小时差异，同时验证 DST 后再次按计划墙上时间运行时会使用当时的新 offset。对现有 06:15/23:45 计划，6:10 的预告触发发生在 DST 切换后并重新计算；目前没有证据证明一般自动应用会延迟或选错主题。需要未来支持 DST 地区的实机验证，尤其是计划边界靠近时钟跳变的情形后，再决定是否更换动态时区来源；
- **配置束崩溃一致性（保留为观察项）**：当前事务可对可捕获异常执行回滚，但无法保证进程强杀/断电时 `config.json`、profile 文件与 Task Scheduler 一起原子提交；这些文件各自合法并不能证明属于同一代配置。暂不引入新的 WAL。出现重启后真实 profile/config 不一致、有新功能依赖这些文件原子成组、健康检查需要验证该不变量，或保存窗口/影响显著扩大时，重新评估轻量恢复日志；
- `main` 已受保护，必需状态检查为精确 job 名 `Windows CI`；分支保护细项按仓库设置维护。
- Authenticode 与 SBOM 不属于本轮 1.0.1 范围；自有 EXE 未签名状态须继续如实说明。

## 非目标

- 不增加三个或更多时段；
- 不增加日出/日落联网计算；
- 不接管 Windows 色温“夜间模式”；
- 不接管壁纸、声音、鼠标指针或桌面图标；
- 不增加后台自动更新服务；
- 不在 1.0 冻结期增加新功能；
- 不为降低统计数字删除关键测试、事务回滚或数据校验；
- 不在缺少机器可读计划和明确授权时清理发布产物或执行 Windows 实机写入。
