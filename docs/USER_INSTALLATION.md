# ThemeScheduler 最终用户安装指南

## 1. 适用范围

本指南面向安装和使用 ThemeScheduler 的普通用户。开发构建、注册表、任务
计划和事务实现细节分别见 [Windows 打包方案](../packaging/README.md) 与
[安装生命周期契约](INSTALLATION.md)。

本指南对应 `0.1.3`，支持 Windows 11 x64，按当前用户安装：

- 不要求预装 Python、uv、虚拟环境或 pywebview；
- 通常不要求管理员权限；
- Windows 11 通常已带有 WebView2 Runtime；缺失时安装器会给出处理提示；
- 不支持 Windows on ARM 的 ARM64 原生环境；
- 不提供后台自动更新。

## 2. 获取与安全验证

正式安装器位于发布目录：

```text
artifacts/releases/0.1.3/dist/ThemeScheduler-Setup.exe
```

正式 SHA-256 以同目录的 `SHA256SUMS.txt` 为准，不从历史说明复制旧版本哈希。

可在安装器所在目录打开 PowerShell 并运行：

```powershell
(Get-FileHash .\ThemeScheduler-Setup.exe -Algorithm SHA256).Hash
Get-Content .\SHA256SUMS.txt
```

本项目没有使用 Authenticode 签名。Windows 可能显示“打开文件—安全警告”、
“未知发布者”或 SmartScreen 页面。只有在文件来自可信发送者且 SHA-256 完全
一致时才继续；不要关闭 Defender、SmartScreen，也不要为本程序创建安全排除。

## 3. 首次安装

1. 双击 `ThemeScheduler-Setup.exe`。
2. 阅读欢迎页和安装位置。程序默认安装到：

   ```text
   %LOCALAPPDATA%\Programs\ThemeScheduler
   ```

3. 按需选择是否创建桌面快捷方式，然后依次确认并安装。
4. 安装完成后打开 ThemeScheduler 主界面。
5. 分别设置昼间和夜间的开始时间、默认应用模式及强调色。
6. 点击“保存并启用”。首次保存会启用计划，但不会立即改变当前 Windows 外观；
   下一次计划边界到达时才自动切换。

安装器会创建开始菜单入口、当前用户“程序和功能”登记及
`\ThemeScheduler` 任务。工作 GUI 不需要常驻；关闭窗口后，计划任务仍按边界
运行。

ThemeScheduler 只管理“默认应用模式”和强调色，不修改“默认 Windows 模式”，
也不控制 Windows 色温功能“夜间模式”。

## 4. 日常配置与维护

可从开始菜单打开 ThemeScheduler。工作界面可以：

- 编辑昼间和夜间的时间、应用模式与颜色；
- 暂停或恢复计划；
- 检查任务和系统集成健康状态；
- 在维护区修复任务、查看日志或打开数据目录。

保存计划不会立即套用主题。如果只是临时改变当前外观，请使用 Windows
“设置 → 个性化 → 颜色”；ThemeScheduler 会在下一次有效计划边界继续工作。

也可以打开“控制面板 → 程序和功能”，选择 ThemeScheduler 后点击“更改”，
直接进入主 GUI 的维护区。

## 5. 修复、重装与升级

主程序文件损坏、入口丢失或需要修复安装时，直接重新运行同版本
`ThemeScheduler-Setup.exe`。Setup 会自动进入“修复 / 重装”，事务式替换程序
文件并修复登记、快捷方式和任务，不要求先卸载。

修复或同版本重装默认保留：

- 配置和暂停状态；
- 昼间、夜间的应用模式及颜色；
- 首次安装外观恢复点；
- 运行日志。

后续版本同样通过新的 Setup 升级。升级前建议保留安装器和重要配置备份；本版本
没有后台自动更新服务。

## 6. 卸载选项

在“控制面板 → 程序和功能”选择 ThemeScheduler 并点击“卸载”。三个选择集中
在同一个卸载向导页面：

| 选项 | 选中时 | 不选时 |
| --- | --- | --- |
| 恢复安装前外观 | 恢复安装时捕获的应用模式和强调色；默认 Windows 模式保持不变 | 保持卸载时的当前外观 |
| 保留配置及昼夜颜色 | 保留配置、状态和两套颜色，便于以后重装继续使用 | 删除这些产品数据 |
| 保留日志 | 保留诊断日志 | 删除日志 |

程序文件、任务、登记、快捷方式和运行缓存无论如何都会删除。若配置和日志均不
保留，整个产品数据根也会删除。卸载结果页点击“退出”后，自清理可能需要数秒；
窗口关闭后不必在任务管理器中手动结束临时卸载进程。

## 7. 数据位置

| 内容 | 默认位置 |
| --- | --- |
| 程序 | `%LOCALAPPDATA%\Programs\ThemeScheduler` |
| 配置、状态、昼夜颜色和日志 | `%LOCALAPPDATA%\ThemeScheduler` |
| 开始菜单快捷方式 | 当前用户开始菜单 |
| 自动任务 | Windows 任务计划程序中的 `\ThemeScheduler` |

不要手工删除程序目录来代替卸载。即使主 EXE 已损坏，也应从控制面板调用独立
卸载器，或先用同版本 Setup 修复。

## 8. 常见问题

### 到达时间但没有切换

打开维护区运行只读健康检查，确认计划未暂停、`\ThemeScheduler` 任务存在且
配置有效。应用自身也必须支持深浅模式并选择“跟随系统”，才会响应 Windows
默认应用模式。

### 收到通知但没有看到右下角横幅

Windows 可能把通知直接归集到通知中心，这与专注模式、通知设置以及通知中心
当时是否打开有关。先检查通知中心，再检查 ThemeScheduler 的 Windows 通知
权限。

### 强调色只有部分界面更新

先等待 Shell 完成刷新。若健康检查确认颜色已写入但任务栏或开始菜单长期不同步，
可在维护区使用需要明确确认的 Explorer 故障恢复；该操作会重启 Explorer，不是
日常切换步骤。

### 安装器显示未知发布者

这是当前版本未使用 Authenticode 的预期结果，不等于文件一定安全。必须同时
确认发送者可信及 SHA-256 一致；无法确认时不要运行。

### 程序损坏后还能卸载吗

可以。安装目录中的独立卸载器不依赖主 GUI 的可执行文件；控制面板卸载入口仍
可清理任务、登记、程序和所选数据。也可以先运行同版本 Setup 修复，再正常使用。

## 9. 已知限制

- 只支持两个固定切换时点，不提供日出、日落或联网时区计算；
- 不接管壁纸、声音、鼠标指针、桌面图标或 Windows 色温夜间模式；
- 强调色切换依赖已在目标 Windows 11 验证、但未公开的主题管理接口；
- 当前没有 Authenticode 签名和后台自动更新；
- `0.1.2` 已在另一台无 Python 的 Windows x64 设备完成安装、计划边界、升级和
  独立卸载验收；单台设备结果不代表所有 Windows 11 组合。
