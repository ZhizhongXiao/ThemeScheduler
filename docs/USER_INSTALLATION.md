# ThemeScheduler 最终用户安装指南

## 1. 适用范围

本指南面向安装和使用 ThemeScheduler 的普通用户。开发构建、注册表、任务
计划和事务实现细节分别见 [Windows 打包方案](../packaging/README.md) 与
[安装生命周期契约](INSTALLATION.md)。

本指南描述当前安装行为。正式可下载版本以
[GitHub 最新正式 Release](https://github.com/ZhizhongXiao/ThemeScheduler/releases/latest)
为准；`1.0.1` 尚未正式发布。支持 Windows 11 x64，按当前用户安装：

- 不要求预装 Python、uv、虚拟环境或 pywebview；
- 通常不要求管理员权限；
- Windows 11 通常已带有 WebView2 Runtime；缺失或检测失败时会显示原生错误提示并停止启动，用户另行安装 Microsoft Edge WebView2 Runtime 后可重试；
- 不支持 Windows on ARM 的 ARM64 原生环境；
- 不提供后台自动更新。

## 2. 获取与安全验证

从 GitHub 正式 Release 下载 `ThemeScheduler-Setup.exe`、`RELEASE-README.md` 和
`SHA256SUMS.txt`。候选目录不是正式下载源；`artifacts/releases/1.0.1/` 仅在
1.0.1 完成冻结和正式发布后使用。

正式 SHA-256 以同一 Release 的 `SHA256SUMS.txt` 为准，不从历史说明复制旧版本哈希。

可在安装器所在目录打开 PowerShell 并运行：

```powershell
(Get-FileHash .\ThemeScheduler-Setup.exe -Algorithm SHA256).Hash
Get-Content .\SHA256SUMS.txt
```

本项目没有使用 Authenticode 签名。Windows 可能显示“打开文件—安全警告”、
“未知发布者”或 SmartScreen 页面。只有在文件来自可信发送者且 SHA-256 完全
一致时才继续；不要关闭 Defender、SmartScreen，也不要为本程序创建安全排除。

## 3. 首次安装

1. 双击 `ThemeScheduler-Setup.exe`。
2. 阅读欢迎页和安装位置。程序默认安装到：

   ```text
   %LOCALAPPDATA%\Programs\ThemeScheduler
   ```

3. 按需选择是否创建桌面快捷方式，然后依次确认并安装。
4. 安装完成后打开 ThemeScheduler 主界面。
5. 分别设置昼间和夜间的开始时间、Windows 模式、应用模式、强调色，以及强调色是否显示在开始菜单/任务栏和标题栏/窗口边框。
6. 点击“保存并启用”。首次保存会启用计划，但不会立即改变当前 Windows 外观；
   下一次计划边界到达时才自动切换。

安装器会创建开始菜单入口、当前用户“程序和功能”登记及
`\ThemeScheduler` 任务。工作 GUI 不需要常驻；关闭窗口后，计划任务仍按边界
运行。

ThemeScheduler 管理 Windows 的浅/深色模式、应用浅/深色模式、强调色及两个显示
位置；它不控制 Windows 色温功能“夜间模式”。

## 4. 日常配置与维护

可从开始菜单打开 ThemeScheduler。工作界面可以：

- 编辑昼间和夜间的时间、两种模式、颜色与强调色显示位置；
- 暂停或恢复计划；
- 检查任务和系统集成健康状态；
- 在维护区修复任务、查看日志或打开数据目录。

### 维护页：计划与程序入口

维护操作按“先检查、再决定是否修复”排列：

| 操作 | 何时使用 | 会做什么 |
| --- | --- | --- |
| 恢复默认时间与通知 | 想恢复计划时间和通知偏好，但保留自己的昼夜外观时 | 把时间设为 06:15 / 23:45，并启用错误与状态变更通知；保留昼夜应用模式、Windows 模式、两个强调色显示位置和 profile 颜色。保存并验证配置及任务，不立即改变 Windows 外观。 |
| 检查任务计划 | 怀疑计划任务缺失、触发时间不符或任务定义漂移时 | 只读比较当前配置生成的预期任务与 Windows 任务计划程序定义；不会修复或改变主题。 |
| 修复任务计划 | “检查任务计划”发现定义不一致后 | 根据当前可信配置重建并读回验证任务；不会改变 Windows 外观。操作前需要确认。 |
| 修复通知身份 | 完整健康检查明确报告通知身份可修复后 | 仅修复 ThemeScheduler 拥有的开始菜单入口、已有桌面入口及通知协议身份；不会擅自创建可选桌面快捷方式。操作前需要确认。 |
| 打开日志目录 | 需要查看自动运行、手动操作和修复事件时 | 打开结构化运行日志所在目录。日志用于追踪事件和结果，不是配置入口。 |
| 打开数据目录 | 需要备份或只读检查配置、状态、昼夜 profile 和事务记录时 | 打开产品数据目录。除非正在按明确的恢复步骤操作，不要手工编辑这些文件。 |
| 启动独立卸载器 | 要卸载 ThemeScheduler 时 | 打开卸载选项，让你决定是否恢复安装前外观、保留配置/颜色或保留日志；卸载前会显示影响并要求确认。 |

“检查任务计划”和“完整健康检查”都是检查，不会代替修复。只有检查报告指出具体可修复问题时，才使用对应的修复操作。维护页底部显示数据目录和“关闭窗口后程序不会驻留后台”的说明；计划页与调试页不重复展示这些提示。

### 调试页：按需复核

一般排查先运行上方的“完整健康检查”，再查看“最近事件”。其余折叠项是供进一步定位使用的只读原始数据：

| 输出 | 适用情形 |
| --- | --- |
| 完整健康检查 | 初步检查配置、状态、profile、程序载荷、任务、Windows 访问能力和通知身份等项目；检查本身不修改配置、任务或 Windows 外观。它可能在数据目录建立并立即清除一次性权限探针；若清理失败会报告。 |
| 最近事件 | 对照最近的自动切换、保存和修复结果；显示最近一小段结构化事件，不等同于完整日志文件。 |
| 任务定义 | 检查任务路径、触发器和动作等当前任务快照。 |
| 状态与昼夜 profile | 对照暂停/上次运行状态及两套外观颜色 profile。 |
| 当前 Windows 外观来源 | 复核实时系统外观、活动主题文件来源及两者是否有差异。 |
| overview 原始数据 | 查看工作台完整状态对象，用于前述摘要不足以定位问题时。 |

完整健康检查旁的“复制摘要”保留为精简诊断摘要。其他输出框旁的复制按钮复制该框当前显示的全部内容，不删减字段；overview 和外观来源等完整数据可能包含本机路径。分享前请检查并按需脱敏，不要直接公开包含个人路径或机器信息的报告。

保存计划不会立即套用主题。如果只是临时改变当前外观，请使用 Windows
“设置 → 个性化 → 颜色”；ThemeScheduler 会在下一次有效计划边界继续工作。

也可以打开“控制面板 → 程序和功能”，选择 ThemeScheduler 后点击“更改”，
直接进入主 GUI 的维护区。

## 5. 修复、重装与升级

主程序文件损坏、入口丢失或需要修复安装时，直接重新运行同版本
`ThemeScheduler-Setup.exe`。Setup 会自动进入“修复 / 重装”，事务式替换程序
文件并修复登记、快捷方式和任务，不要求先卸载。

修复或同版本重装默认保留：

- 配置和暂停状态；
- 昼间、夜间的完整外观计划；
- 首次安装外观恢复点；
- 运行日志。

后续版本同样通过新的 Setup 升级。升级前建议保留安装器和重要配置备份；本版本
没有后台自动更新服务。

## 6. 卸载选项

在“控制面板 → 程序和功能”选择 ThemeScheduler 并点击“卸载”。三个选择集中
在同一个卸载向导页面：

| 选项 | 选中时 | 不选时 |
| --- | --- | --- |
| 恢复安装前外观 | 新安装恢复点还原两种模式、强调色及显示位置；旧版恢复点按其原有范围恢复 | 保持卸载时的当前外观 |
| 保留配置及昼夜颜色 | 保留配置、状态和两套颜色，便于以后重装继续使用 | 删除这些产品数据 |
| 保留日志 | 保留诊断日志 | 删除日志 |

程序文件、任务、登记、快捷方式和运行缓存无论如何都会删除。若配置和日志均不
保留，整个产品数据根也会删除。卸载结果页点击“退出”后，自清理可能需要数秒；
窗口关闭后不必在任务管理器中手动结束临时卸载进程。

## 7. 数据位置

| 内容 | 默认位置 |
| --- | --- |
| 程序 | `%LOCALAPPDATA%\Programs\ThemeScheduler` |
| 配置、状态、昼夜颜色和日志 | `%LOCALAPPDATA%\ThemeScheduler` |
| 开始菜单快捷方式 | 当前用户开始菜单 |
| 自动任务 | Windows 任务计划程序中的 `\ThemeScheduler` |

不要手工删除程序目录来代替卸载。即使主 EXE 已损坏，也应从控制面板调用独立
卸载器，或先用同版本 Setup 修复。

## 8. 常见问题

### 到达时间但没有切换

打开维护区运行只读健康检查，确认计划未暂停、`\ThemeScheduler` 任务存在且
配置有效。应用自身也必须支持深浅模式并选择“跟随系统”，才会响应 Windows
默认应用模式。

### 收到通知但没有看到右下角横幅

Windows 可能把通知直接归集到通知中心，这与专注模式、通知设置以及通知中心
当时是否打开有关。先检查通知中心，再检查 ThemeScheduler 的 Windows 通知
权限。

### 强调色只有部分界面更新

先等待 Shell 完成刷新。若健康检查确认颜色已写入但任务栏或开始菜单长期不同步，
可在维护区使用需要明确确认的 Explorer 故障恢复；该操作会重启 Explorer，不是
日常切换步骤。

### 安装器显示未知发布者

这是当前版本未使用 Authenticode 的预期结果，不等于文件一定安全。必须同时
确认发送者可信及 SHA-256 一致；无法确认时不要运行。

### 程序损坏后还能卸载吗

可以。安装目录中的独立卸载器不依赖主 GUI 的可执行文件；控制面板卸载入口仍
可清理任务、登记、程序和所选数据。也可以先运行同版本 Setup 修复，再正常使用。

## 9. 已知限制

- 只支持两个固定切换时点，不提供日出、日落或联网时区计算；
- 不接管壁纸、声音、鼠标指针、桌面图标或 Windows 色温夜间模式；
- 强调色切换依赖已在目标 Windows 11 验证、但未公开的主题管理接口；
- 当前没有 Authenticode 签名和后台自动更新；
- 历史 `0.1.2` 已在另一台无 Python 的 Windows x64 设备完成安装、计划边界、升级和
  独立卸载验收；这不替代 `1.0.1` 最终候选的变更驱动验收，也不代表所有 Windows 11 组合。
